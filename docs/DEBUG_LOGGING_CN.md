# 客户端调试模式

在登录界面开启“调试模式”，然后正常输入用户 Token、登录和选择节点。
首次默认关闭，选择会保存在用户配置的 `debug_mode` 字段；再次打开客户端时会恢复。
调试开关只增加日志，不改变认证、心跳失败处理、服务端命令或隧道停止规则。

## 记录内容

- 每行日志有本地时间、毫秒和时区。
- `[ENV]`：程序/Qt/操作系统/架构、PID、路径、心跳间隔。
- `[ACTION]`：按钮对应操作、登录状态、忙碌状态、进程是否运行、隧道数量。
- `[HTTP #编号]`：请求路径、脱敏请求摘要、会话代数、超时、耗时、HTTP 状态、网络错误编号、响应大小、白名单响应摘要。
- HTTP 的连接、发送、重定向、TLS 协议/加密套件和证书校验错误；不会忽略证书错误。
- `[SESSION]` / `[AUTH]`：会话失效、过期请求丢弃、授权节点及端口/协议/DPI 权限摘要。
- `[HEARTBEAT]` / `[COMMAND]`：心跳发起、跳过、返回结果、命令编号/类型、重复命令去重；ACK 请求也有请求编号。
- `[PROCESS]`：启动/状态变更/PID、停止来源、重启、停止超时、强制结束、退出码及退出状态。
- `[CONFIG]` / `[LEASE]`：配置路径/大小、安全的连接选项和租约释放；不输出完整 TOML。
- `[FRPC stdout/stderr]`：frpc 原生日志；调试模式为本次生成的 TOML 设置 `log.level = "debug"`、控制台输出及无颜色。
- `[QML]`：界面引擎告警。

## 停止来源

普通模式也会记录“frpc 停止来源”。所有停止调用必须显式传入来源，没有无来源的默认停止参数。

| 来源 | 含义 |
| --- | --- |
| `ui.stop_all_tunnels` | 停止全部入口 |
| `ui.stop_single_tunnel:名称` | 关闭一个隧道，可能重启剩余隧道 |
| `runtime.apply_new_configuration` | 正在运行时应用新配置 |
| `server.command.stop_frpc id=编号` | 服务端下发的停止命令 |
| `auth.logout:原因` | 退出/重新鉴权/心跳业务拒绝等下线流程 |
| `auth.return_to_login:原因` | 清理登录状态并返回登录界面 |

进程状态编号：0=未运行，1=启动中，2=运行中。退出状态：0=NormalExit，1=CrashExit。
`intentional=true` 表示代码调用过停止，不代表一定是用户点击。

## 获取日志

连接后的“日志”页显示文件路径，并提供“复制日志”按钮。
文件默认在 Windows 的 `%LOCALAPPDATA%/frp-control/frp-control-client/logs/`，实际路径以日志页为准。
每次开启创建一个 `debug-时间-PID-代数.log` 文件；累计到约 10 MiB 时轮转，保留当前文件和一个 `.previous` 分段，单次会话约 20 MiB。
下一次轮转只替换该会话更早的 `.previous` 分段；不同会话的文件不自动删除，可自行清理。
关闭调试模式停止写盘；“清空”只清界面日志，不清文件。界面日志保留最多 10,000 行/约 2 MiB，复制的是当前可见日志。

用户 Token、已识别的 FRP 运行时 Token、密码类字段会脱敏。HTTP 摘要采用字段白名单，不输出原始响应、证书、私钥、完整配置或转发业务数据。
日志仍包含节点地址、隧道地址、文件路径和服务端提示，请只发给可信的人。
排查断开时，请提供停止前后的 `[ACTION]`、`[PROCESS]`、`[HEARTBEAT]`、`[COMMAND]` 记录，或对应日志文件及 `.previous` 分段。

本次改动不修正 Windows 下的 `QProcess::terminate()` 停止策略，也不推断原先断开的触发原因；新增日志用于明确定位。
